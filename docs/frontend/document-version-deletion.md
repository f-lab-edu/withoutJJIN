# 버전 히스토리의 DocumentVersion 삭제

## 화면과 요청

- 히스토리에서 `uploadedBy`와 현재 로그인한 회원 ID가 같은 버전에만 삭제 버튼을 표시한다. 서버의 업로더·워크스페이스 소속 검사는 별도로 유지한다.
- `PROCESSING` 상태의 버튼은 비활성화한다. 변환 대기·실패·완료 버전은 삭제를 요청할 수 있다.
- 브라우저 기본 확인창에 선택한 버전 번호·원본 파일명과 원본 Word·PDF·피드백 삭제 범위를 표시한다. 취소하면 DELETE 요청을 보내지 않는다.
- 삭제 직전에 `/api/v1/auth/me`로 계정을 다시 확인하고 최신 `csrfToken`을 `X-CSRF-TOKEN` 헤더로 전달한다.
- 요청은 `DELETE /api/v1/workspaces/{workspaceId}/documents/{documentId}/versions/{documentVersionId}`이며 본문이나 S3 저장 키를 보내지 않는다.
- 삭제 확인·전송·재조회 중에는 중복 삭제, 원본 다운로드와 목록 갱신을 막는다. 일반적인 조회 중에도 기존 버튼 비활성화를 유지한다.
- 업로더 표시 이름·파일명·안내 문구는 textContent 또는 브라우저 기본 확인창의 텍스트로 표시한다.

## 응답과 목록 갱신

- 204는 본문을 읽지 않고 성공으로 처리한다. 선택한 버전을 화면에서 제거한 뒤 문서와 버전 목록을 다시 조회한다.
- 최신 표시와 개수는 남은 목록으로 갱신한다. 마지막 버전을 삭제해도 Document를 유지하며 동일한 Document에 새 버전을 추가하는 링크를 표시한다.
- 삭제 성공 후 재조회가 실패하면 "버전 삭제는 완료됐지만 목록을 갱신하지 못했어요"로 구분해서 안내한다. 목록 새로고침으로 재조회할 수 있다.
- 401·403은 오래된 비공개 목록을 비우고 로그인·권한 오류를 표시한다. 삭제 후 재조회에서도 계정이 바뀌면 새 계정의 화면으로 조용히 전환하지 않는다.
- DELETE의 404는 목록을 다시 확인한다. 실제로 버전이 없으면 목록 갱신을 안내하고, 목록에 여전히 남아 있으면 삭제 성공으로 처리하거나 숨기지 않는다. 로그인 확인 요청의 404는 버전 없음으로 취급하지 않는다.
- 409는 목록을 다시 조회하고 최신 변환 상태를 표시한다. PROCESSING으로 바뀌었다면 삭제 버튼이 비활성화된다.
- 통신 오류·중단·서버 오류로 삭제 결과를 확정할 수 없으면 읽기 요청으로 실제 목록을 확인한다. DELETE를 자동 재전송하지 않는다.
- 204 또는 재조회로 없어진 것을 확인한 ID는 현재 화면에서 기억하여 이전 조회 결과가 삭제한 버전을 다시 표시하지 못하게 한다. 화면 이탈 시 이 상태를 지운다.

## 늦은 응답과 화면 이탈

- 삭제 확인과 요청 동안 조회 타이머를 멈추고, 끝난 뒤 변환 대기·진행 중인 버전이 있으면 5초 간격 조회를 재개한다.
- 취소된 타이머는 실행 토큰과 세대 번호를 확인하여 새 조회나 다운로드를 방해하지 않는다.
- 확인·삭제·재조회 중 화면을 떠나면 요청을 중단하고, 늦은 응답으로 목록이나 메시지를 다시 그리지 않는다.
- 기존 원본 다운로드의 중복 차단·계정 재확인·서명 URL 비저장 동작을 유지한다.

## 정적 파일 반영

`document-history.html`의 모듈 식별자를 `delete-version-68`로 변경했다. 실행 중인 Spring에 정적 파일과 삭제 API가 반영되지 않았다면 다시 빌드·실행하고 히스토리를 새로고침한다. HTTP 404 이후 목록에 버전이 계속 남아 있으면 API 배포 상태도 확인한다.

204는 DB 삭제와 S3ObjectDeletionTask 등록 완료를 뜻하며 실제 S3 파일 삭제 완료는 아니다. S3 작업자 실행 설정과 권한·버킷 버전 관리 제약은 `docs/operations/s3-object-deletion.md`를 참고한다.
