# 문서 목록 카드 (#62)

워크스페이스 파일 화면에서 문서 목록을 먼저 표시하고, 화면 너비에 따라 두 열 또는 한 열 카드로 배치한다.

- 카드에 Document.title, 최신 버전 번호, 실제 DocumentVersion 개수, Document 생성 시각 및 최신 PDF 변환 상태를 표시한다.
- GET /api/v1/workspaces/{workspaceId}/documents 응답에 versionCount를 추가한다. revision은 현재 남은 DocumentVersion의 최대 versionNumber(없으면 0)이며 versionCount와 다를 수 있다. 번호 발급을 위한 Document.revision은 삭제해도 줄이지 않는다.
- versionCount는 변환 작업 유무나 상태와 관계없이 해당 Document의 DocumentVersion 행 수를 센다. 버전이 없으면 0이다.
- 카드의 PDF 보기와 새 버전 업로드는 기존 동작을 유지한다.
- 새 파일 추가는 선택한 기존 문서 대상을 해제하고 업로드 입력으로 이동한다. 업로드 진행 중·완료 처리 재시도 대기 중에는 다른 업로드로 전환하지 않는다.
- 파일명은 textContent로 표시한다. 변환 대기·변환 중에는 기존 5초 간격 상태 갱신을 유지한다.
- 카드의 버전 히스토리 보기에서 /workspaces/{workspaceId}/documents/{documentId}/history로 이동한다.
- 히스토리는 실제 DocumentVersion 목록을 최신순으로 표시하고 업로더·업로드 시각·원본 파일명·변환 상태를 표시한다.
- PDF 보기 주소는 /workspaces/{workspaceId}/documents/{documentId}/versions/{documentVersionId}/review이다. 최신 변환 상태와 관계없이 선택한 버전의 PDF를 발급받고, PDF 응답의 DocumentVersion으로 피드백을 조회한다.
- 원본 다운로드는 매번 로그인 계정을 확인하고 URL을 새로 발급한다. URL은 브라우저 저장소에 보관하지 않으며 중복 클릭·화면 이탈 후 늦은 응답을 처리한다.
- 새 버전 추가는 워크스페이스의 uploadDocumentId 쿼리로 같은 Document를 선택한다. 알 수 없는 대상은 업로드를 막고, 이미 남아 있는 완료 처리 재시도를 우선한다.
- 히스토리의 PDF 변환 대기·실행 중 상태는 5초마다 갱신한다. 빈 목록·오류·다시 로그인 상태를 표시한다.
- 이번 작업에는 버전 삭제와 수정 요청·검토 상태 관리가 포함되지 않는다.

## 히스토리 화면 검증

2026-11-15 검증 결과:

- 전체 JavaScript 테스트 307개 통과. 버전 API 응답 검증, 계정 변경, 중복 다운로드, 늦은 응답 무시, 선택한 버전 PDF·피드백 유지 및 기존 완료 처리 재시도 우선순위를 포함한다.
- 서버 관련 테스트 36개 통과. 히스토리·선택 버전 PDF HTML 응답, 비로그인 시 로그인 이동, 로그인 후 복귀 경로 및 기존 문서 조회 API 인증 응답을 포함한다.
- 서버 테스트는 임시 MySQL 스키마와 임시 계정을 사용했으며 종료 후 정리했다.
- Chrome에서 카드 → 히스토리 → V1 PDF와 V1 피드백 → 히스토리 복귀를 확인했다. 최신 V3이 변환 대기 중이어도 V1을 열 수 있고 PDF 다시 열기 후에도 V1을 유지한다.
- 원본 버튼의 중복 요청 차단과 한글 다운로드 파일명을 확인했다. 다운로드 URL은 브라우저 저장소에 저장하지 않는다.
- 새 버전 추가는 같은 Document를 업로드 대상으로 선택한다. 잘못된 대상은 새 Document 업로드로 조용히 전환하지 않는다.
- 빈 목록, 권한 오류, 계정 변경 후 목록 제거 및 변환 상태 자동 갱신을 확인했다.
- 1365px, 900px, 640px, 390px, 320px에서 긴 파일명과 버튼 배치의 가로 넘침이 없는지 확인했다.

브라우저 검증은 실제 로컬 PDF.js와 테스트 PDF를 사용하며 API·S3 응답은 임시 응답이다. 실제 사용자 문서·AWS 다운로드 및 실제 모바일 기기의 터치 검증은 별도로 확인한다.

정적 파일이 실행 중인 Spring에 반영되지 않으면 Spring을 재시작한 뒤 문서 목록의 버전 히스토리 보기에서 확인한다.
