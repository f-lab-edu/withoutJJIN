# PDF 피드백 화면 레이아웃 및 검증 (#60)

## 변경 내용

- 문서 제목은 화면 너비에 따라 18~22px로 표시한다.
- 문서 제목과 버전 표시를 함께 배치하고 상단 여백을 줄인다.
- 데스크톱 화면의 최대 너비 제한을 없애고 PDF·피드백 패널 간격을 16px로 줄인다.
- 데스크톱 피드백 패널 너비는 화면 크기에 따라 280~360px로 조정한다.
- 900px 이하에서는 PDF와 피드백 패널을 세로로 배치하고 상단 버튼은 줄바꿈한다.
- PDF를 열 때 컨테이너의 clientWidth에서 좌우 padding을 제외한 너비로 페이지를 그린다. 렌더링 너비 상한 1,200px은 유지한다.
- PDF 그리드의 열이 컨테이너 안에 들어오도록 제한하고 세로 스크롤바 공간을 미리 확보한다.
- PDF와 피드백 패널의 독립 스크롤 및 페이지에 대한 비율 좌표 방식은 유지한다.

- 넓은 화면에서도 렌더링 너비 상한이 유지되는 테스트 추가.

## Chrome 검증

실제 PDF.js와 개인정보가 없는 3페이지 테스트 PDF를 사용했다. 로그인·문서·피드백 API와 S3 PDF 응답은 임시 응답으로 대체했으며 운영 DB·AWS에는 접근하지 않았다.

- 1920×1080, 1365×1000, 1024×768, 900×844, 390×844, 320×740에서 PDF가 컨테이너 너비에 맞춰 표시되고 가로 스크롤이 발생하지 않는지 확인했다.
- 긴 파일명은 901px을 포함한 데스크톱·모바일 전환 경계에서도 제목과 버튼이 가로로 넘치지 않는지 확인했다.
- 로그인 만료 안내와 다시 로그인 버튼의 표시를 확인했다.
- 피드백을 클릭해도 바깥 페이지와 피드백 패널의 스크롤 위치가 바뀌지 않고 PDF 내부에서 이동하는지 확인했다.
- 영역 선택 후 화면 너비를 줄여도 선택 좌표와 저장된 피드백 영역·번호의 연결이 유지되는지 확인했다.
- 모바일 에뮬레이션에서 터치 드래그로 영역을 선택하고, 선택 모드를 끈 상태에서 터치로 PDF를 스크롤하는 동작을 확인했다.

두 번째 커밋 전후의 PDF 패널 안쪽 가용 너비 비교:

| 화면 크기 | 변경 전 | 변경 후 |
| --- | ---: | ---: |
| 1920×1080 | 1086px | 1471px |
| 1365×1000 | 911px | 948px |
| 1024×768 | 570px | 655px |

가용 너비와 실제 PDF 페이지 너비는 다를 수 있다. 페이지 렌더링은 최대 1,200px이며, 변경 전에는 padding을 포함한 계산 때문에 페이지가 가로로 넘쳤다.

## 검증 한계와 실제 화면 확인

- 위 검증은 Chrome 데스크톱 및 모바일 에뮬레이션 결과다. 실제 Android·iOS 기기에서 확인한 결과가 아니다.
- 자동화된 일부 터치 탭에서 click 이벤트가 생성되지 않아 취소·모드 전환·피드백 버튼은 마우스 클릭으로 확인했다. 실제 기기에서 버튼 터치 동작을 별도로 확인해야 한다.
- 창 크기 변경 시 기존 canvas는 CSS로 축소된다. 창을 크게 늘린 뒤 새 너비로 다시 렌더링하려면 `PDF 다시 열기`를 사용한다.
- 정적 파일이 실행 중인 Spring에 반영되지 않았다면 리소스를 다시 반영하거나 Spring을 재시작한 뒤 새로고침한다.
- 실제 문서에서 가로 스크롤, 영역 선택·취소, 피드백 번호·클릭 이동 및 모바일 버튼 터치를 최종 확인한다.

이번 작업은 PDF 조회 화면 개선이며, DOCX→PDF 변환 엔진과 글꼴 지원 범위는 변경하지 않는다.
